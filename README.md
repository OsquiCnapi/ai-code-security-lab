## Overview

This project analyzes the security of PHP web applications generated by an AI/LLM without explicit security requirements, then evaluates how the AI improves when security requirements are specified.

A **Time Clock web application** was used as the target — a realistic small business tool with login, role-based access, shift entry, and supervisor search functionality built with Apache, PHP, and MySQL.

## Vulnerabilities Found (Version 1)

| # | Vulnerability | Location | Severity |
|---|--------------|----------|----------|
| 1 | SQL Injection | Login form | Critical |
| 2 | SQL Injection | Supervisor search | Critical |
| 3 | Reflected XSS | Supervisor search | High |

### SQL Injection — Login Bypass
The login query concatenated user input directly:
```php
"SELECT * FROM users WHERE username='$username' AND password='$password'"
```
Payload: `' OR 1=1-- -` → full authentication bypass.

### SQL Injection — Supervisor Search
The search query was also unsanitized:
```php
"WHERE u.username='$search'"
```
Payload: `' OR '1'='1'-- -` → all employee shifts exposed.

### Reflected XSS
Search input echoed without encoding:
```php
value="<?php echo $search; ?>"
```
Payload: `"><script>alert('XSS')</script>` → arbitrary JavaScript execution.

## Security Controls Implemented (Version 2)

| Fix | Method |
|-----|--------|
| SQL Injection | Prepared statements (`mysqli_prepare`) |
| XSS | Output encoding (`htmlspecialchars`) |
| Password storage | Bcrypt hashing (`password_hash`) |
| Session security | Auth check before every internal page |

## Remaining Issues (Both Versions)

- No CSRF tokens on forms
- No rate limiting on login endpoint
- No audit logging for shift submissions or supervisor searches
